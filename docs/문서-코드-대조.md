## 요약

두 문서는 공격을 **Evil Twin + Deauthentication 2종**(+ PMKID는 미구현)으로 기술하고, 시각화는
**Streamlit**, 탐지는 **실시간 Scapy 스니퍼**로 설계돼 있다. 현재 코드는 그 뼈대에서 **핵심 스택이
교체·확장**됐다.

> 한 줄 요약: 문서는 "Evil Twin + Deauth를 Streamlit·실시간 Scapy로 보여주는 도구"였고,
> 현재 코드는 **① 시각화를 정적 HTML + `bridge.py`로, ② 탐지를 오프라인 pcap 분석으로** 교체하고
> **③ Beacon Flood 공격, 웹 명령 콘솔, 학습/실습 2모드, 다수 교육 시나리오**를 새로 얹은 형태다.

## 1. 스택·아키텍처 변경 (문서 → 현재 코드)

| 항목 | 문서(보고서/발표) | 현재 코드 |
|---|---|---|
| **시각화** | **Streamlit** 웹 대시보드 `dashboard.py` + rich 터미널 | **정적 HTML 대시보드**(`dashboard_html/` = index.html·app.js·scenarios.js·styles.css) + **`bridge.py`**(표준 라이브러리 HTTP 서버, pip 불필요). Streamlit 제거 |
| **탐지 엔진** | **실시간** Scapy sniffer + multiprocessing Queue, 지연 500ms 이내 | **오프라인 pcap 분석기** `detector/et_detector.py` (파일 주석: "실시간 탐지가 아니라 정확한 오프라인 분석이 목적"). 공격 → 자동 캡처(pcap) → 오프라인 판정 흐름 |
| **대시보드 동작 모드** | 단일 실시간 탐지 화면(경보 팝업·게이지) | **학습 모드 / 실습 모드 2분리** — 학습은 `scenarios.js` 목업 단계 재생(서버 불필요), 실습은 실제 로그 3초 폴링 + **명령 콘솔** |
| **Deauth 구현** | Scapy로 직접 프레임 생성·주입 | 데모/스크립트상 **aireplay-ng** ("DoS method: Aireplay") 기반 |
| **공격 도구** | aircrack-ng, hostapd, dnsmasq (+"더 추가 예정") | 위 + **mdk4·ettercap·tcpdump·iptables** 등으로 구체화 (Beacon Flood=mdk4, 스니퍼=ettercap) |

## 2. 추가된 것 (문서에 없던 신규 기능·공격)

- **Beacon Flood 공격 (완전 신규)** — `beacon_flood/et_beacon_flood.sh`(mdk4) + `et_capture.sh`.
  문서엔 없던 두 번째 실증 공격이며, `et_detector.py`도 Evil Twin에 더해 **Beacon Flood 판정 로직** 포함.
- **웹 명령 콘솔 + 웹훅 연동 (신규)** — `bridge.py`가 화이트리스트 명령만 서버에서 실행(`/api/exec`),
  `et_logger.sh` 웹훅 수신(`/api/events`), 통합 상태 JSON 제공(`/api/state`).
  "브라우저 콘솔에서 공격/탐지 명령 실행" 개념은 문서에 없음.
- **학습용 시나리오 라이브러리 (신규, 대시보드 전용)** — `scenarios.js`에 단계별 교육 시뮬레이션 다수.
  문서의 2개 공격을 훨씬 초과하며, 현재 **evil-twin · beacon-flood · karma · arp-spoofing · wps** 5종.
  단, karma·arp·**wps**는 아직 **대시보드 시뮬레이션만** 있고 실제 공격 스크립트/탐지는 없음.
- **운영 스크립트 재편** — `et_check_deps.sh`(의존성 점검/설치), `et_logger.sh`(이벤트 로거),
  `et_stop.sh`(공격 중지), `evil_twin/lab_victim_ap.sh`(랩용 피해 AP).
  문서의 `requirement.sh`/`detector.py`/`dashboard.py` 구성과 다름.

## 3. 문서엔 있으나 코드에 없음/변경됨

- **PMKID 공격 모듈** — 문서에서 "일정 부족으로 미구현" 명시 → 현재 코드에도 없음(상태 유지).
  (대시보드 학습 시나리오에 있던 유사한 `handshake`(WPA 핸드셰이크/PMKID)는 제거함.)
- **실시간 멀티프로세싱 500ms 파이프라인(COR-004 등)** — 탐지가 오프라인 pcap 분석으로 방향이
  바뀌면서 사실상 해당 없음.
- **일반 사용자용 팝업 경보(SIR-001)** — 문서 단계에서 이미 교육용으로 수정/삭제됐고, 코드도
  교육용 대시보드로 구현됨(방향 일치).
